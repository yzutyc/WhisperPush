消息推送系统需求文档

文档版本：1.0
最后更新：2026年5月13日
目标平台：iOS / Android

本系统旨在构建一个类似 Bark 的自托管消息推送服务，支持用户通过 HTTP API 向自己的移动设备发送自定义通知。系统包含服务端（Python FastAPI）和客户端（Flutter 跨平台 App）。

一、项目概述

开发一套完整的自托管消息推送解决方案，允许用户通过简单的 HTTP 请求向自己的 iOS/Android 设备发送通知。系统强调安全性、可扩展性和用户体验，支持多种内容格式和高级通知特性。

二、核心功能需求

2.1 用户账户系统

  • 用户注册（邮箱/用户名 + 密码）
  • 用户登录（JWT Token 认证）
  • 会话管理（Token 刷新机制）

2.2 Secret 秘钥管理

  • 每个用户可创建多个 Secret 秘钥
  • 秘钥可命名（如“生产环境”、“测试环境”）
  • 支持查看、复制、删除秘钥
  • 秘钥在数据库中以哈希形式存储（非明文）

2.3 消息推送功能

  • 通过 HTTP API 推送消息（需携带有效 Secret）
  • 支持三种内容格式：
    • 纯文本（text/plain）
    • Markdown（text/markdown）
    • HTML（text/html，需安全过滤）
  • 消息包含标题、正文、时间戳
  • 支持消息分组（Group）
  • 支持消息级别（Level: active, timeSensitive, critical）

2.4 消息接收与展示（App 端）

  • 消息列表界面（仿短信 UI）
  • 消息详情页（根据内容类型渲染）
  • 未读消息标记
  • 消息搜索与过滤
  • 后台推送通知（集成 FCM/APNs）

2.5 服务器配置

  • App 内可配置自定义服务器地址
  • 支持 HTTPS 强制校验

三、技术栈

组件 技术选型
后端框架 Python 3.10+ + FastAPI
数据库 PostgreSQL (推荐) / MySQL
ORM SQLAlchemy + Alembic
前端框架 Flutter 3.0+
推送服务 HTTP Webhook + Firebase Cloud Messaging (FCM) + Apple Push Notification service (APNs)
部署 Docker + Docker Compose

四、API 接口设计

4.1 认证接口

方法 路径 功能 认证
POST /api/v1/auth/register 用户注册 无
POST /api/v1/auth/login 用户登录 无
GET /api/v1/auth/me 获取当前用户信息 Bearer JWT

4.2 Secret 管理接口

方法 路径 功能 认证
POST /api/v1/secrets 创建新 Secret Bearer JWT
GET /api/v1/secrets 列出所有 Secret Bearer JWT
DELETE /api/v1/secrets/{secret_id} 删除指定 Secret Bearer JWT

4.3 消息推送接口（外部调用）

方法 路径 功能 认证
POST /api/v1/push 推送消息 Header: X-Secret-Key

请求体示例：

{
  "title": "服务器告警",
  "body": "# CPU 使用率过高\n当前负载: 95%",
  "content_type": "markdown",
  "group": "monitoring",
  "level": "timeSensitive"
}

4.4 消息查询接口（App 使用）

方法 路径 功能 认证
GET /api/v1/messages 分页获取消息列表 Bearer JWT
GET /api/v1/messages/{msg_id} 获取单条消息详情 Bearer JWT
PATCH /api/v1/messages/{msg_id}/read 标记消息为已读 Bearer JWT

五、数据库设计

5.1 users 表（用户）

字段 类型 说明
id Integer (PK) 用户ID
username String(50) 用户名（唯一）
email String(100) 邮箱（唯一）
password_hash String(128) 密码哈希值
created_at DateTime 注册时间

5.2 secrets 表（用户秘钥）

字段 类型 说明
id Integer (PK) 秘钥ID
user_id Integer (FK) 关联用户ID
secret_key_hash String(64) Secret 哈希值（SHA256）
name String(50) 秘钥名称（可选）
created_at DateTime 创建时间
is_active Boolean 是否启用

5.3 messages 表（消息）

字段 类型 说明
id Integer (PK) 消息ID
user_id Integer (FK) 接收用户ID
title String(100) 消息标题
body Text 消息正文
content_type String(20) 内容类型：text/markdown/html
group String(50) 消息分组（可选）
level String(20) 消息级别：active/timeSensitive/critical
created_at DateTime 创建时间
read Boolean 是否已读

六、前端页面设计（Flutter）

6.1 启动页（SplashScreen）

  • 功能：应用启动时短暂显示 Logo
  • 逻辑：检查本地 Token → 有则进主页，无则进登录页

6.2 登录页（LoginPage）

  • 内容：用户名/邮箱、密码输入框，“注册”和“登录”按钮
  • 功能：调用登录 API，保存 JWT 到本地

6.3 注册页（RegisterPage）

  • 内容：用户名、邮箱、密码、确认密码
  • 功能：调用注册 API，成功后自动登录

6.4 消息列表页（MessageListPage）

  • 内容：
    • 顶部 AppBar（含“设置”图标）
    • 消息列表项（标题、摘要、时间、未读标记）
  • 功能：下拉刷新、上滑加载、点击进入详情页

6.5 消息详情页（MessageDetailPage）

  • 内容：标题、时间戳、正文（按类型渲染）
  • 功能：标记为已读、复制内容
  • 渲染方案：
    • text → Text widget
    • markdown → flutter_markdown 包
    • html → flutter_html 包（带 XSS 过滤）

6.6 设置页（SettingsPage）

  • 内容：
    • 服务器地址配置（文本输入）
    • Secret 管理（列表 + “新建”按钮）
    • “退出登录”按钮
  • 功能：保存服务器 URL、管理 Secret 秘钥

七、安全与扩展性

7.1 安全措施

  • 所有 API 强制 HTTPS
  • Secret 秘钥仅用于推送鉴权，不用于登录
  • 数据库中 Secret 存储 SHA256 哈希值
  • HTML 内容使用 flutter_html + 安全策略过滤 XSS
  • JWT Token 设置合理过期时间（7天）

7.2 扩展功能（未来）

  • 消息有效期（自动清理过期消息）
  • Web 客户端支持
  • 消息模板管理
  • 多设备同步
  • 自定义铃声/图标（iOS 15+）

八、部署与运维

  • 提供 Docker Compose 部署脚本
  • 支持 Cloudflare Worker / Serverless 部署
  • 内置健康检查接口（/health）
  • 日志记录与监控（可选集成 Prometheus）
